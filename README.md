# Whatsminer Monitor (Android / Kotlin)

اپلیکیشن اندروید برای مانیتور کردن دستگاه‌های ماینر **Whatsminer** روی شبکه محلی (وای‌فای).
برنامه به صورت خودکار کل ساب‌نت وای‌فای گوشی را اسکن می‌کند، ماینرهایی که پورت API آن‌ها
(4028) باز است را پیدا می‌کند، و برای هرکدام موارد زیر را نمایش می‌دهد:

- آدرس IP دستگاه
- مدت زمان روشن بودن (uptime)
- دمای میانگین و دمای هر هش‌بورد
- هشریت کل و هشریت هر هش‌بورد
- دور فن ورودی و خروجی
- مصرف برق تقریبی
- نسخه فریمور
- کدهای خطای فعال (با توضیح فارسی و راه‌حل، از بانک اطلاعاتی جامع)
- درآمد روزانه/ماهانه تخمینی (زنده، بر اساس قیمت و هشریت شبکه لحظه‌ای)

## تغییرات این نسخه (رفع باگ) — به‌روزرسانی دوم

بعد از تست نسخهٔ قبلی، مشخص شد بخش کنترل دستگاه (ریبوت/تغییر پول) هنوز کار نمی‌کرد. با بررسی
سورس یک اپ مشابه (که کاربر ارائه داد) روی همین دستگاه‌ها، معلوم شد **دلیل اصلی این بود که
Whatsminer برای دستورهای نوشتنی (ریبوت/تغییر پول) به پروتکل باینری TCP:4028 با رمزنگاری
AES که قبلاً پیاده‌سازی شده بود متکی نیست؛ به‌جایش همان پنل مدیریت وبی (LuCI) که با مرورگر هم
باز می‌شود استفاده می‌شود.** یعنی مشکل «رمز اشتباه» به‌خاطر الگوریتم امضا نبود، بلکه اساساً
پروتکل اشتباهی برای نوشتن استفاده می‌شد.

تغییرات:

- **کلاینت جدید `network/LuciMinerClient.kt`**: با پنل وب HTTPS دستگاه (پورت‌های ۴۴۳ و ۴۴۳۳،
  هر دو امتحان می‌شوند) وارد می‌شود (`/cgi-bin/luci` با فیلدهای فرم `luci_username`/`luci_password`،
  دقیقاً مثل ورود با مرورگر)، توکن CSRF و فیلدهای فعلی فرم پول‌ها را از صفحهٔ
  `/cgi-bin/luci/admin/network/btminer` می‌خواند، فرم به‌روزشده را POST می‌کند، و در پایان با
  یک درخواست به `/cgi-bin/luci/admin/status/btminerstatus/restart` دستگاه را ری‌استارت/اعمال
  می‌کند. این حالا **روش اصلی** ریبوت و تغییر پول است. کد قبلی TCP:4028 + AES (در
  `WhatsminerClient.kt`) به‌عنوان روش پشتیبان (fallback) نگه داشته شده، برای مدل‌ها/فریمورهایی
  که ممکن است این پنل وب را نداشته باشند.
- **رمز عبور سراسری**: قبلاً رمز برای هر IP جداگانه ذخیره می‌شد، یعنی اگر چند ماینر با رمز
  یکسان داشتید، برنامه برای هرکدام جداگانه رمز می‌خواست. الان (`CredentialsStore.kt`) یک رمز
  سراسری ذخیره می‌شود: به محض وارد کردن رمز درست برای یک دستگاه، همان رمز برای بقیهٔ دستگاه‌ها
  هم به‌صورت خودکار امتحان می‌شود و دوباره درخواست نمی‌شود؛ فقط اگر دستگاهی رمز متفاوتی داشت،
  دوباره (فقط برای همان یکی) پرسیده می‌شود.
- **هشریت شبکه**: مقدار پیش‌فرضِ آخرین‌راه‌حل (وقتی نشد زنده گرفت) به همان مقداری که در اپ مرجع
  دیده شد (۹۹۴.۶۸ اگزاهش) به‌روزرسانی شد.
- کاتالوگ کدهای خطا (`ErrorCodes.kt`) با ساختار واقعی proto اپ مرجع (فیلدهای `id`/`reason`/`action`)
  مقایسه و تأیید شد که ساختار داده‌ای که قبلاً پیاده‌سازی شده بود کاملاً صحیح است.

## تغییرات نسخهٔ اول (رفع باگ)

نسخه اولیه سه مشکل داشت که در آن به‌روزرسانی رفع شدند:

1. **کد خطا شناسایی نمی‌شد** — کاتالوگ کدهای خطا از فایل جامع `errors_fa.pb` (۱۶۰ کد با
   توضیح/راه‌حل فارسی) در `model/ErrorCodes.kt` بازسازی شد؛ برخی کدها بسته به شمارهٔ هش‌برد
   الگودار هستند (مثلا 300/301/302) که به‌درستی مدیریت می‌شوند. علاوه بر این، روند دریافت کد
   خطا (`get_error_code`) در `WhatsminerClient.kt` مقاوم‌تر شد: بین ۸ درخواست پشت‌سرهم به هر
   دستگاه یک مکث کوتاه گذاشته می‌شود و در صورت شکست یک تلاش مجدد انجام می‌شود.

2. **درآمد تخمینی و قیمت دلار به‌روز نبود** — هشریت کل شبکه بیت‌کوین که در محاسبهٔ درآمد
   استفاده می‌شد عددی ثابت و منسوخ بود؛ الان از دو منبع عمومی زنده (mempool.space و
   blockchain.info) گرفته می‌شود. قیمت دلار/بیت‌کوین هم هر ۶۰ ثانیه خودکار رفرش می‌شود.

همچنین آیکون‌های ارسالی کاربر (دستگاه ماینر، هش‌بردهای شمارهٔ ۱ تا ۳، فن، اعلان، وای‌فای)
جایگزین/اضافه به آیکون‌های قبلی برنامه شدند (`res/drawable-nodpi/`).

## نحوه بیلد گرفتن

1. پوشه پروژه را در **Android Studio** (Hedgehog یا جدیدتر) باز کنید — Open an existing project.
2. صبر کنید Gradle Sync تمام شود (اولین بار دانلود دیپندنسی‌ها زمان می‌برد).
3. گوشی/شبیه‌ساز را انتخاب کرده و Run بزنید، یا از منوی `Build > Generate Signed Bundle / APK` برای گرفتن APK استفاده کنید.

> این پروژه در محیط sandbox قابل کامپایل نبود (به SDK اندروید و ریپازیتوری Google Maven
> دسترسی نداشت)، بنابراین کد به‌صورت دستی و با دقت طبق مستندات رسمی نوشته شده. منطق حساس
> (الگوریتم امضا/رمزنگاری API و کاتالوگ کدهای خطا) جداگانه در محیط Kotlin/JVM ساده کامپایل
> و با مقادیر مرجع تست شد، اما پیشنهاد می‌شود بعد از Sync اول یک بیلد امتحانی بگیرید.

## نکته مهم درباره ارتباط با ماینر Whatsminer

دو مسیر ارتباطی جدا برای دو کار متفاوت استفاده می‌شود:

**۱) خواندن اطلاعات (مانیتورینگ)** — پورت **4028**، پروتکل JSON روی TCP خام (مشابه cgminer
API)، بدون نیاز به رمز عبور. دستورهایی مثل `summary`, `devs`, `pools`, `get_error_code` و
غیره از همین مسیر خوانده می‌شوند (`WhatsminerClient.kt`).

**۲) نوشتن/کنترل (ریبوت، تغییر پول)** — پنل مدیریت وب دستگاه (LuCI روی HTTPS، پورت ۴۴۳ یا
۴۴۳۳)، دقیقاً همان پنلی که با مرورگر هم قابل مشاهده است: ورود با فرم `luci_username`/
`luci_password`، سپس POST کردن فرم پول‌ها در صفحهٔ `/admin/network/btminer`، و ری‌استارت با
یک درخواست به `/admin/status/btminerstatus/restart` (`LuciMinerClient.kt`). نام کاربری/رمز
پیش‌فرض کارخانه‌ای هر دو **admin/admin** است. چون این دستگاه‌ها معمولاً گواهی HTTPS خودامضا
(self-signed) دارند، این کلاینت گواهی را به‌صورت دستی (فقط برای همین اتصال محلی، نه کل برنامه)
می‌پذیرد.

اگر پنل وب روی یک دستگاه در دسترس نبود (نه به‌خاطر رمز اشتباه)، برنامه به‌صورت خودکار به روش
قدیمی‌تر (API خام روی 4028 با امضای md5-crypt + رمزنگاری AES-256) هم به‌عنوان پشتیبان تلاش
می‌کند.

چون نام دقیق فیلدهای JSON بین نسخه‌های مختلف فریمور کمی فرق دارد، `WhatsminerClient.kt` چند
نام محتمل برای هر مقدار (دما، فن، هشریت و ...) امتحان می‌کند. اگر مقداری برای دستگاه شما "—"
نمایش داده شد، بهترین کار این است که با یک ابزار مثل `nc` یا `telnet` دستور `{"cmd":"summary"}`
و `{"cmd":"devs"}` را مستقیم به پورت 4028 دستگاه بفرستید، خروجی JSON واقعی را ببینید، و نام
کلید مربوطه را به لیست‌های `findDouble/findInt/...` در همان فایل اضافه کنید.

## مجوزهای مورد نیاز

- `INTERNET` و `ACCESS_NETWORK_STATE` برای اتصال TCP به ماینرها روی شبکه محلی.
- `ACCESS_WIFI_STATE` برای تشخیص ساب‌نت وای‌فای.

توجه: چون فقط از سوکت خام TCP استفاده شده (نه HTTP)، نیازی به مجوز موقعیت مکانی (Location)
برای اسکن شبکه نیست.

## بیلد خودکار با GitHub Actions (بدون نیاز به Android Studio)

یک workflow در مسیر `.github/workflows/build.yml` اضافه شده که به‌محض push کردن روی
شاخه `main`/`master` (یا اجرای دستی)، خودِ گیت‌هاب پروژه را بیلد می‌کند و فایل APK را
می‌سازد — لازم نیست خودت Android Studio نصب کنی.

**نحوه دریافت APK بعد از push:**

1. پروژه را طبق بخش بعدی (آپلود در گیت‌هاب) در یک ریپازیتوری جدید push کن.
2. توی خود گیت‌هاب برو به تب **Actions** بالای صفحه ریپازیتوری.
3. اجرای (run) با نام **Build APK** رو باز کن و صبر کن سبز بشه (چند دقیقه طول می‌کشه).
4. پایین صفحه‌ی همون run، بخش **Artifacts** رو باز کن و فایل
   `whatsminer-monitor-debug-apk` رو دانلود کن — یک zip شامل `app-debug.apk`.
5. APK رو به گوشی اندرویدت منتقل کن (تلگرام به خودت، ایمیل، یا کابل)، بازش کن و نصب کن.
   چون از گوگل‌پلی نیست، اندروید ممکنه بخواد اجازه‌ی «نصب از منابع ناشناس» رو بدی —
   این تنظیم رو موقع نصب خودش نشونت میده.

اگر اجرای workflow قرمز (fail) شد، روی همون run کلیک کن، لاگ مرحله‌ای که خطا داده رو
باز کن و متن خطا رو برام بفرست تا دقیقاً همون رو درست کنم.
